# Antigravity observer upgrade recovery — 0.8.2

Release record: this document preserves evidence and decisions for its named revision. For current behavior and superseding changes, use [the capability matrix](../../guides/capabilities.md) and [changelog](../../../CHANGELOG.md).

## Why sessions remained

Inspection of the running installation found host version 0.8.1 with a staged hook observer still at 0.8.0. Updating the application had not replaced the separately staged executable used by existing hook commands. Two retained local Antigravity reports consequently lacked process ownership, so the new exact-process checks could not establish their exit. Waiting longer could not supply that missing evidence.

Windows process snapshots also retained some terminated process objects. A process name in a snapshot alone was insufficient to establish that Antigravity was still running.

## Implemented repair

- Startup refreshes an existing managed observer from the bundled executable at its stable hook path. It does not install a previously unconfigured integration or rewrite hook settings. A locked-file failure is logged and retried every five seconds until replacement succeeds.
- Fresh hooks capture the actual Antigravity ancestor PID and process creation time. The existing 500 ms lifetime observer handles subsequent exit and PID reuse.
- For legacy PID-less reports in the local provider cache, recovery can establish exit only when a complete native census finds no running `agy.exe`. It opens matching process handles, checks their termination state, and validates live executable names. Terminated objects do not count as running. Any inaccessible matching process, incomplete enumeration, or live Antigravity process blocks this fallback. Session age and bridge disconnection alone never authorize removal.
- Recovery rechecks the cached revision and identity before committing an ordered exit report. Ended and purged entries are excluded. Generic external producer rows are outside this legacy fallback.
- Confirmed exit immediately moves the same session into Archive. Result context, request content, deletion guards, CLI history, and project files remain intact. Fresh verified SessionStart can reactivate the same record.

First-time setup still requires Connect and the provider's normal trust review. Automatic binary refresh preserves existing registration; it does not grant new hook permissions. A legacy session cannot be individually resolved through the zero-process fallback while another Antigravity process is running.

## Verification

The actual running installation accepted two ordered exit reports through the existing loopback transport. Its subsequent API snapshot showed two archived Antigravity sessions and zero Antigravity sessions remaining in the main list. The staged observer reported 0.8.2 afterward. This was an API/state check, not visual inspection or a real interactive `/exit` acceptance run.

Seven isolated native WebView2/IPC upgrade checks passed: replacement without Connect, version match, byte-for-byte preservation of hook settings, legacy removal from Sessions, preserved archived output, restart without resurrection or repeated ending, and exclusion of unverified external rows. Run `npm run test:observer-upgrade` against the smoke build with its matching helper; evidence is written to the ignored artifacts directory.

Eight native lifetime checks also passed with explicitly owned Windows process fixtures: retention while alive, orderly exit, forced exit, context preservation, bounded delivery, fresh resumption, exit during downtime, and rejection of forged PID/transport loss. The observed fixture exit-to-removal interval was 45 ms, not a latency guarantee. These fixtures made no model calls and did not run the actual Antigravity interactive `/exit` flow.

Regression checks passed 17 JavaScript tests, 23 core tests, 22 helper tests, and 10 native unit tests. Installer compilation and staging are separate from these behavior checks. Broader native display validation and real-provider interactive acceptance remain outstanding.
