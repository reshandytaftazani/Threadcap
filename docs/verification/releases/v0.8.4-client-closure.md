# Confirmed client closure in 0.8.4

Confirmed terminal or CLI-session closure now moves every provider's session into Archive immediately. This replaces the previous Codex/OpenCode delay and Off behavior. Existing preference values remain stored for compatibility, but Settings explains the current immediate-closure policy. Task results, unresolved requests, CLI history, and project files remain intact. Completion, missing heartbeats, bridge loss, and unknown process observations do not prove closure.

## OpenCode client ownership

The 0.8.3 server plugin could observe sessions while OpenCode's persistent server survived a closed TUI. Version 0.8.4 adds a TUI plugin beside the server plugin. Connect preserves unrelated CLI settings and plugin entries and registers the TUI plugin in `cli.json`. Restart existing OpenCode CLI clients after Connect; the shared server does not need to restart. Configuration that cannot be parsed is left unchanged and setup reports the error.

The observer reports session IDs selected by that TUI. The bundled helper captures its actual parent PID and process creation time through Windows APIs; incoming JSON cannot supply that identity. Native monitoring checks those identities rather than treating the shared server as a terminal. A session stays visible while any verified client owns it. Closing the last client archives it, including after forced process termination. Plugin cleanup alone is not exit evidence.

Background server events retain context but cannot reactivate a closed CLI session. A fresh verified TUI can reactivate the same session without creating a duplicate. Closure markers survive application restart. A TUI retains ownership of visited sessions until it exits; closing an individual internal view is not separately observed.

Older locally cached OpenCode sessions have no client identity. Recovery archives these only after a complete native process census confirms that no OpenCode CLI client remains. Missing command lines, access denial, unknown observations, or a possible client prevent that migration. External producer rows are excluded. Exact ownership checks run in the existing native observer loop; legacy census attempts are bounded and spaced apart. A separate one-time store migration archives retained context that already has confirmed end/closure evidence; it does not infer closure from disconnection, and preserves explicit closure-restoration markers.

## Other providers and limits

Antigravity retains its exact hook-ancestor PID and creation-time observer. Its Stop hook still means turn completion, not CLI exit. Codex uses official session-end events and verified native pane observations. Unbound legacy Codex sessions cannot be declared closed from age or disconnection alone. This change does not add terminal navigation or response delivery capabilities.

## Verification

Real OpenCode 2.3.0 TUI clients were tested against an isolated native island and persistent server, without model prompts. Checks covered two clients sharing one session, the first exit leaving the session visible, the final exit archiving it while the server stayed alive, rejected background reactivation, application restart, and fresh-client resumption. A separate run exercised forced termination of an owned test client. The sequence was also repeated with spaces in fixture paths.

Rust tests cover exact parent capture, multiple-client aggregation, unknown observations, configuration preservation, immediate archival for all providers, protected request context, and closed-session reactivation barriers. These checks do not establish remote/Web/GUI client lifetime, every terminal host, mixed-DPI behavior, or general exact-tab navigation.

The installed 0.8.4 upgrade preserved all 17 existing session identities: 16 archived records and one active Codex session. No record with confirmed closure/end evidence remained in the main list. The installed host and helpers matched the staged release, accounting for the expected NSIS bundle marker. OpenCode registration succeeded with an existing UTF-8 BOM configuration; unrelated settings and plugins were preserved. The Antigravity status-line command, backup, and preferences were also checked. These are observations from this upgrade, not a guarantee about unverified legacy identities on other machines.
