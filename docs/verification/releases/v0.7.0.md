# Roadmap implementation, version 0.7.0

Release record: this document preserves evidence and decisions for its named revision. For current behavior and superseding changes, use [the capability matrix](../../guides/capabilities.md) and [changelog](../../../CHANGELOG.md).

The six approved additions and subsequent UI, attention, and completion refinements are implemented in the native Rust/Tauri application. This report separates implemented behavior from reference and platform coverage that remains open. No approval/reply delivery or OpenCode adapter is implied.

## Delivered behavior

| Area | Implementation |
| --- | --- |
| Session retention | Archive eligible context from selected detail; inspect and restore it under Settings > Behavior. Rust persists archive metadata with canonical revisions. Running work and unresolved requests are protected. A confirmed process end can make a last-known running record eligible without changing its task lifecycle. |
| Automatic archiving | Optional, initially off, persisted in SQLite. A minute-based native sweep requires explicit end evidence, at least 24 hours, disconnection, and no unresolved request. Sweeps pause while the panel or Settings is open so rows cannot disappear under an interaction. Explicitly restored end episodes stay visible instead of being immediately archived again. Idle, completion, or transport loss alone is insufficient. No CLI files or history are deleted. |
| Restore on new work | A fresh accepted prompt or identified pending request restores an archived session. Duplicates and stale reports are rejected before mutation. Native helper-cache recovery uses a separate recovery entry point and cannot restore archived rows. Older helpers without prompt metadata require updating or manual restoration. |
| Shared UI | Medium-weight compact summaries, closer visual grouping, denser flat session rows, shared control tokens, and a shorter saved-session strip. Compact, hover, detail, overview, terminal selection, and Settings retain the same anchored black surface. Hover height stays unchanged. |
| Truthful summaries | Connected sessions count as live; disconnected retained context counts as saved. Working counts require live running evidence. Global transport loss suppresses live claims. Requests and failures retain priority, with full connection context available on opening. |
| Application mark | Original candidate A, selected after actual-size comparison with B and C at 16/32/64/128 pixels. A top opening and broad lower silhouette remain readable at tray scale; B loses separation at small sizes, while C resembles a generic U. A dark backplate keeps the final mark distinct on light surfaces. SVG and generated Windows PNG/ICO resources are included. Provider marks are separate. |
| Provider motion | Stable Codex, Antigravity, and OpenCode marks keep their existing state companions. Idle companions now briefly move after long rests, with 11/13/9-second provider-specific cycles. Hidden loops pause; Reduce motion stops spatial and companion animation. Recovered terminal states use a settled pose instead of replaying a celebration. |
| Guided setup | Codex provider detail contains Detect CLI, Connect, Review hooks, and Verify activity. Detection and registration use existing bounded native actions. Review remains a user action in Codex, not a trust bypass. A fresh connected event during setup is required for verified activity. Back, retry, and navigation retain setup context. Unsupported providers explain their limits. |
| Automatic request reveal | Behavior preference defaults on. Fresh connected requests open focused detail from compact without a focus call. Open surfaces, Settings, and typing are protected. Request navigation follows episode order, with server-owned request timestamps for reconnect snapshots. Dismissed, deferred, duplicate, and snapshot requests do not reopen later. |
| Completion cooldown | After ten seconds, the quiet compact completion settles to idle. Canonical completed state and result remain available. New work cancels the old timer; snapshots restore silently; opened results are not closed by the timer. |

## Session-delivery measurement and optimization

`tests/native/measure-delivery.cjs` launches an isolated native host, temporary profiles, and disk-backed stores. It measures process launch, the core acceptance timestamp, DOM mutation, and a double-requestAnimationFrame opportunity. Core acceptance precedes its commit, so the reported core-to-DOM interval includes commit, IPC, and DOM work; it is not a pure IPC measurement. A frame opportunity is not a physical display measurement.

The initial comparison found warm median launch-to-frame opportunities of 85 ms for the direct helper and 454 ms through PowerShell. A subsequent 24-sample comparison produced:

| Invocation | Warm samples | Median | p95 | Fresh helper-cache sample |
| --- | --- | --- | --- | --- |
| Direct helper | 7 | 85 ms | 98 ms | 448 ms |
| CMD launching helper | 7 | 110 ms | 142 ms | 132 ms |
| PowerShell wrapper | 7 | 455 ms | 503 ms | 531 ms |

These are small samples from this machine with no model calls and no missing reports, not general latency guarantees. The first sample per mode uses a fresh helper cache; subsequent samples reuse a warm cache. Raw samples are in `artifacts/session-delivery.json`; the initial comparison is retained separately.

The hook generator now directly invokes the quoted Rust executable for absolute paths that are safe under CMD. Paths containing shell-sensitive characters retain the encoded PowerShell fallback. The approach follows the [Codex 0.169.0 Windows command runner](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/hooks/src/engine/command_runner.rs). Real CMD invocation tests cover both paths, including spaces, apostrophes, percent signs, Unicode, emoji, and shell-like prompt text. Both old and new owned definitions are recognized during safe registration updates and removal. No durability or event-ordering guarantees were removed.

Run Reconnect after upgrading, then review the changed hook definitions in Codex using `/hooks`. The application never grants hook trust itself. Larger retained histories and broader concurrent/cold-start latency characterization remain useful follow-up work. The 24-sample comparison above is retained in `artifacts/session-delivery-comparison24.json`; a later run additionally exercises six concurrent hook processes sharing one helper cache.

Application icon resources can be reproduced with `npm.cmd run icons:build` directly from the original SVG, without Orca or image-generation services.

## Reference and platform limits

Lumi 1.0.3 was opened for reference without changing its settings or resetting onboarding. Hidden-window capture produced a black frame; desktop capture showed its compact clock surface, not its setup flow. Therefore no claim is made that Lumi's setup animation was observed or reproduced. The implemented guide follows the approved island motion rules. No Lumi assets were extracted.

The primary implementation is Rust/Tauri. The legacy Python bridge does not expose native archive actions or the native sweep. Other providers retain their existing integration limits. Mixed-DPI movement, every taskbar position, fullscreen policies, every accessibility scaling combination, large histories, and a real trusted CLI/model conversation are not fully certified.
